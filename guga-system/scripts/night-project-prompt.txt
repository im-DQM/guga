若批准清单没有未完成项 → 什么都不做，直接结束（不要写报告）。

## 第 2 步 · 干活（规则是硬约束）
先 `skill_view(name='guga-hub')` 看这个前端/后端的约定与已知坑，再动手。
- **只许碰这些**：
  - 从 `/home/ubuntu/stack/hub/index.html` 复制一份到 `/home/ubuntu/.hermes/previews/preview-<YYYY-MM-DD>-<短名>.html`，在**副本**上改；
  - 改好后 `cp` 到 `/home/ubuntu/stack/hub/preview-<YYYY-MM-DD>-<短名>.html`，这样主人用浏览器打开 `http://localhost:8080/preview-<YYYY-MM-DD>-<短名>.html` 就能看到。
- **严禁碰**：`/home/ubuntu/stack/hub/index.html`（线上界面）、`Caddyfile`、`todo_api.py`、任何 systemd 服务、cron 任务定义、SSH/防火墙/域名；严禁重启 caddy 或任何服务。
- **改动要小**：只做这一条，尽量少改代码、容易回退；不重构、不加新依赖、不改视觉基调（靛紫 + 发丝描边那一套）。
- **自测**：
  - 把 `<script>` 抽出来跑 `node --check`（命令见 guga-hub 技能）——语法必须过；
  - 用浏览器工具打开预览地址截图确认没坏（浏览器不可用就跳过，报告里写"未截图"）；
  - 自测不过就修；修不动就把预览删掉，报告里写明原因。
- **时长**：控制在 30 分钟内。做不完就停下，把已完成的进展写进报告。

## 第 3 步 · 写报告（唯一投递通道）
把报告写到 `/home/ubuntu/.hermes/cron/output/abb926a25cad/$(date +%F_%H-%M-%S).md`，格式**严格**如下（第一行的 `---` 不能少，收件箱靠它切正文）：

```
---
【夜间预览】<一句话标题>

- 批准项：<批准清单里那条原文>

- 改了：<1–2 句，人话>

```

不要用 markdown 表格，不要在末尾加 `•`（那是聊天界面专用的结束符）。
