# 咕嘎调度：/N 前缀（主人 2026-10-25 定）

界面不加按钮、不动 hub。**聊天里以 `/N` 开头（N=0…8）＝这条活派给咕嘎 N 号**；没前缀＝一号我自己答。
「它们各自维护自己的记忆和技能，只是你来调用他们」——我是调度者，不是替身。

## 一条前缀消息怎么处理

1. 认出编号（`/8 看看 swap` → 八号）。消息正文去掉前缀，原话照传，不替我改写需求。
2. 取料：`python3 ~/.hermes/scripts/guga.py brief <N>`（SOUL + MEMORY + WORKFLOW 全给子 agent）。
3. 调用：`delegate_task` 起一个子 agent，goal 里放去掉前缀的原话，context 里放
   「你是咕嘎N号……（brief 全文）」，并要求它**自己用 `guga.py log/remember/workflow` 回写**。
4. 汇报：回复以「N号：」开头，一两句结论 + 需要主人拍板的地方；不搬子 agent 的过程。
5. 特殊情况：三号/四号/五号是**外部机器/外部服务**，不是子 agent——按 `INDEX.md` 的老办法调
   （`wb.py`、`lv_exec.py`、`ssh win-asus`），但同样用它们自己的工作流与记忆文件。

## 每个咕嘎自己的三件套

| 文件 | 作用 |
| --- | --- |
| `guga<N>/SOUL.md` | 我是谁、管什么、不越什么界 |
| `guga<N>/MEMORY.md` | 跨天要记住的事实（`guga.py remember`） |
| `guga<N>/WORKFLOW.md` | 我的工作流：接活→干活→交付→收尾自评；末尾「经验」段只增不删 |

**自我优化闭环**：每次干完，子 agent 必须写 journal（发生了什么）＋ 判断有没有可复用经验写进 WORKFLOW
的经验段（这次卡在哪、下次怎么做）。每周复盘时把反复出现的经验并进 WORKFLOW 正文，别让它只是流水账。

## 规矩

- 派活前若会影响主人的东西（改文件、发消息、动服务），先一句话说要做什么再动。
- 子 agent 拿不准的，回报给我，我汇总成选项请主人拍板——**不替主人做决定**。
- 各家的记忆只写自己那份，别串味；一号的 MEMORY 不装它们的过程细节。
- 二号的编号不回收（飞书停用中，别派活）。
