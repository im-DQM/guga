# 咕嘎职责索引（一号维护 · 2026-10-15 起）

总目录 `~/.hermes/guga/`，八个咕嘎平行排开：`guga1/` … `guga8/`。
每个子目录统一三件套：**SOUL.md**（我是谁、管什么、边界）、**MEMORY.md**（自己的记忆）、**journal/**（记事）。
干活前先查这张表，再叫对应的人；细节进各自目录，跨项目的做法进技能与 `knowledge/procedures.md`。

**每个咕嘎另有 `WORKFLOW.md`（2026-10-25 起）**：接活→干活→交付→收尾自评的流程，末尾「经验」段由它自己边干边写、只增不删。
**调用方式（2026-10-25 主人定）**：界面不加按钮——聊天里以 `/N` 开头（N=0…8）就是派给咕嘎 N 号，没前缀归一号。
一号负责调用与回写：`guga.py brief/log/remember/workflow`，规矩见 `guga/DISPATCH.md` 与技能 `guga-dispatch`。

## 规矩

- **工作区（`~/workspace`）的规矩是"一个项目一个目录"**：根目录只放 `CLAUDE.md`（零号的规则书）与项目目录；新项目先建目录，散文件按项目归类进对应目录。
- **新机器统一归六号**、不递增编号；只有**新角色**才开新编号（零号=编码咕嘎，2026-10-15 主人指定）。
- 派活前先告诉主人「派谁、为什么」，再动手。
- 每个咕嘎的细节在各自 `SOUL.md`；当前状态在各自 `MEMORY.md`；干活留痕在各自 `journal/`。
- **脚本真身一律放各自 `guga<N>/scripts/`**；`~/.hermes/scripts/` 下只放**几行的启动器**（真实文件，不是软链——cron 会把软链判成"解析到目录外"直接拦掉），启动器 exec 真身并把 cron 参数透传。
- 台账与日志放各自 `guga<N>/state/`，做事留痕放 `journal/`。
- 六号的旧路径 `~/.hermes/guga6` 是指向 `guga/guga6` 的软链，常驻服务靠它零改动运行；别删。
