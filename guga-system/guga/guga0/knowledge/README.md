# 零号的沉淀库（编码能力账本）

这里是咕嘎0号自己的**能力积累**，不是给主人看的笔记。目的只有一个：**同一个坑只踩一次，下一次开工先站在上一次的结论上。**

## 什么时候写

- **收工前必写**（项目做到一个段落、或 `PROGRESS.md` 有更新时）：把这次新学到的、踩到的、改了两次才对的东西，按格式追加进对应文件。
- 一次收工 **最多 3 条**，宁可少写。凑数的条目会让整个库贬值。
- 不写日记、不写进度（进度归 `PROGRESS.md`）、不抄网上教程。

## 写什么（够格的四类）

1. **踩过的坑**：报错原文 → 根因 → 怎么确认 → 怎么改。下次看到同样报错能秒认。
2. **定下来的做法**：这件事以后一律这么做（构建、目录、错误处理、日志），以及为什么。
3. **想清楚的概念**：用自己一句话讲明白，讲不清的不写。
4. **能复用的代码**：放在哪个项目路径 + 一行说明它解决什么。不贴长代码。

## 条目格式（照抄）

```
## YYYY-MM-DD · 一句话标题（动词开头）
- 场景：在做什么的时候碰上的
- 现象/报错：原样贴关键行
- 根因：一句话
- 结论/做法：以后怎么办
- 出处：项目名 或 题目来源
```

## 分区

| 文件 | 装什么 |
| --- | --- |
| `cpp-language.md` | 语言本身：标准版本、所有权、模板、STL、常见 UB |
| `build-and-tools.md` | CMake、编译链接、依赖、工具链、Git |
| `debug-and-perf.md` | 调试、内存、并发、性能、问题定位 |
| `engineering.md` | 工程约定：错误处理、日志、命名、提交前自查 |

## 查的时机

- 新项目开工：四个文件扫一遍（它们应该一直很短）。
- 报错卡住超过 10 分钟：先 `grep` 沉淀库再继续查。
