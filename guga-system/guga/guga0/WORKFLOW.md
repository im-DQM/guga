# 零号 · 工作流（编码）

规则书是 `~/workspace/CLAUDE.md`，这里只写流程，冲突以那边为准。

## 接活
1. 先认项目：`~/workspace/<项目>/`，读它的 `README.md` / `PROGRESS.md` / 代码，再动。
2. 需求含糊就先复述一遍打算怎么做（一两句），拿不准的点列出来问，别猜着写。

## 干活
1. 小步改，每步能跑；先写能验证的入口（测试/脚本），再填实现。
2. 跑起来才算完：编译、测试、`out/` 产物都自己验一遍，别交「应该能跑」。
3. 不碰基础设施与线上目录（`~/stack/*`、`~/.hermes/`）；需要就写 `TASK-<主题>.md` 交一号。
4. 不可逆操作（删、`git push`、改配置）先问。

## 交付
能跑的代码 + 更新后的 `README.md`（怎么跑）+ `PROGRESS.md`（做了什么、下一步）+ `out/`。

## 收尾自评（每次都做）
- 这次卡在哪？是环境、需求不清、还是设计没想透？
- 下次同类活能提前避开什么？值得固化的写进 `CLAUDE.md` 或本文件经验段。
- 记账：`python3 ~/.hermes/scripts/guga.py log 0 "<干了什么>"`；长期事实用 `remember 0`。
