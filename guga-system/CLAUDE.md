## 目录规矩（重要）

- 工作区根目录**只放两样东西**：这份 `CLAUDE.md`，以及**一个项目一个目录**。
- **新建项目先建目录**：`~/workspace/<项目名>/`（短名、小写、中划线分隔，不用空格和中文）。不要往根目录丢散文件。
- 每个项目目录里自带的四件套：`README.md`（这是什么、怎么跑）、`PROGRESS.md`（进度与关键决策）、`out/`（产物、截图、日志）、`notes/`（随手记）。
- 临时试验放该项目目录下的 `notes/` 或 `/tmp`，不要留在根目录。
- 现有项目：`dqmguga/` —— 咕嘎 hub（群页与手机版）相关图纸、进度与产出。

## 干活规矩

- **先读再动**：动手前先看该项目的 `README.md` / `PROGRESS.md` / 图纸；改动前用一两句说清计划。
- **不碰基础设施**：Caddy、DNS、端口、域名、systemd 服务、`/home/ubuntu/stack/` 下的线上目录（`hub/`、`remote/`、`todo_service/`）都不是我该改的——那是咕嘎一号的活。需要改就**写进报告**，交给一号。
- **不可逆操作先问**：删文件、`rm -rf`、改线上配置、动别人的目录，以及 **force push / 改写历史**，先说明再等确认。
  日常 `git push` 到自己项目的新分支是常规操作，不必每推一次都问。
- 产出留在自己项目目录里；不要往 `~/stack`、`~/.hermes` 里写文件。
- 用中文交流，回复短：不写过程叙述，做完报「改了什么、验证了什么、还剩什么」。

## 交付标准

- 卡住了、或需要权限/凭据/线上改动，直接说清楚卡在哪、试过什么，别硬编造结果。
- 写完的脚本要能幂等重跑；报错原样贴出来，别吞。
