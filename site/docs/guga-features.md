# 咕嘎系统 · 功能文档

版本：2026-10-17　｜　维护：咕嘎一号　｜　归属：私人云端 Agent（自建 · 单用户）

---

## 一、这是什么

一套**自建的私人云端 Agent 系统**。内核是 Hermes Agent（Nous Research 开源），跑在一台腾讯云轻量服务器上，一年到头不关机；外壳是一个自己写的网页（hub），手机和电脑都能进。它做的事可以概括成一句话：

> **把「日常琐事、学习节奏、远程操作、多个外部 AI 的调用」收进一个门里，由一个管家（咕嘎一号）统筹，其余成员各管一摊。**

三个特征决定了它的形态：

1. **自建**：不依赖任何 SaaS 的对话界面，界面、后端、任务调度全在自家服务器。内核与模型都能换，数据和记忆留在自己手里。
2. **单用户**：只服务主人一个人。没有多租户、没有分享链接（除了给外人用的接入页）。
3. **国产模型 + 国产云**：模型走 DeepSeek（可切），服务器广州，域名已备案，境内直连。

访问方式：`https://dqmguga.site`（公网，门卫后面）／`http://localhost:8080`（隧道内网，免密后门）。

## 二、核心功能

### 2.1 管家对话（hub 主页 `/`）

这是最常用的入口，就是和咕嘎一号聊天。

- **流式对话**：走持久运行通道（`/v1/runs` + 事件流），一条消息一个字一个字地推回来，断开能续、不会丢。
- **渲染约定**（这套界面自有的一套轻量指令，模型在正文里写、前端识别）：
  - 单行 `::options` 后面每行「1. 文字」→ 变成**可点按钮**，点了就等于把这句话发出去。主人挑方案时点一下就行，不用打字。
  - 单行 `::sysinfo` → 渲染成**资源面板**（磁盘 / 内存 / 交换）。
  - 单行 `•` → 渲染成界面底部那个**蓝色小圆点**（每次回复的收尾标记）。
  - `http…` 一律变成可点链接。
- **附件投递**：输入框左边一个回形针，点选、拖进来、`Ctrl+V` 粘图都行；选中的文件在输入框上方排成小芯片（图片显示圆形缩略图）。只发文件不写字也允许。文件落到服务器 `uploads/日期/` 下，单件上限 64 MB，我在服务端按路径读它——图片直接看，PDF / Word / Excel / 代码能解析。
- **看得到图**：聊天通道里贴 `MEDIA:` 标签不生效（只有别的端点才认），所以看图的做法是把图放进 hub 静态目录，给一个可点链接，点开新标签看。
- **音效**：一条回复跑完「叮」一声；被打断是另一声。顶栏有喇叭开关。

### 2.2 语音与手机

- **手机版 `/m.html`**：会话抽屉 + 聊天 + 语音输入 + 待办 / 站点 / 咕嘎群三个抽屉入口，是主页的精简版。
- **语音输入**：输入框旁的麦克风走浏览器自带的语音识别。**已知限制**：安卓 Chrome 的识别是把声音送到境外服务器转写，这条网在国内走不通，所以手机端语音目前不可用；桌面端可用。要真修得把转写搬到自家服务器（录音上传 + 本地模型），方案已列给主人、尚未动手。

### 2.3 待办系统

- **唯一真源**：服务器上一份 `todos.md`，按日期分节，条目就是 `- [ ]` / `- [x]`，可以带 `@日期 时刻` 做「到点提醒」。
- **三档视图**（右侧面板）：**今天 / 明天 / 长期**。长期是纯清单，不挂期限、不参与每日播种。
- **每日固定项**：吃药（22:00）、学习项目、刷两道算法题、看八股文——每天第一次读清单时自动插到顶部，每天只播一次种，当天删掉不会自己回来。
- **到点提醒**：每 5 分钟扫一遍，有到点没做的条目就提醒。
- **改法**：只通过脚本改（增删改查一套命令），我在对话里替主人动手，主人不用记语法。
- **规矩**：未完成的条目不自动挪到次日，必须主人点头才动。

### 2.4 定时简报与提醒

| 时间 | 内容 |
| --- | --- |
| 08:00 | **早安早报**：问候 + 今日待办简报 + 当天节奏提示 |
| 22:00 | **晚报**：未完成逐条解读（是什么、为什么没做完）+ 可执行建议 + 请他规划明天 + 饮食收口提醒 + 待批提案（选项按钮） |
| 23:00 | **晚安**：问候 + 洗漱睡觉提醒（目标是每晚睡足 7 小时） |
| 每 5 分钟 | **到点提醒** |
| 周六 09:00 | **周复盘**：一周承诺、卡住的事、下周计划，跟他问答对齐 |
| 每天 22:00 | **热点日报**（咕嘎斥候产，见 2.9） |

**投递方式是「不即时推送」**：这些输出先落到服务器上的收件箱，主人打开界面时顶部横幅一次性领取。他要的是「打开就看到」，不是手机被打扰。飞书上那份早晚报是另开的单向同步（见 2.10）。

### 2.5 夜间自动化（人睡着时它干活）

| 时间 | 干什么 |
| --- | --- |
| 01:00 | 上网广泛参考被认可的 agent 工具与产品做法，写进想法池 |
| 02:00 | **只做主人点头批准的项**，产出预览页 + 报告 |
| 03:00 | 只读自检（服务、磁盘、日志）+ 清 7 天前的旧备份 |
| 03:40 | 交换空间巡逻：占用过高才出声，顺手清残留的浏览器会话 |
| 每半小时 | 清浏览器残留进程 |

铁律：**夜间工程只做「批准清单」里的条目，清单空就什么都不做**。任何新想法先由晚报用选项征求同意，绝不自行挑活。

### 2.6 人生规划页 `/plan.html`

- **四段位**：按「连续达成的目标数」每天自动判（破壁 / 千锤 / …，只升不降），当前在打的那一行标出来。
- **三阶段**：断链 → 2026-11-15、登岸 → 2027-01-15、夺旗 → 2027-04-15，每阶段显示「第 N / 30 天 · 到某日」。
- 判据只读主人真在用的文件（待办勾选、上床时间、投递记录表），算不出来的条件（offer、体能有变化、公开发布）由我手动置位。
- 与今日任务同步：今天的清单那一行会高亮。

### 2.7 咕嘎群 `/group.html`

主人 + 各咕嘎的一个群聊，手机优先，3 秒刷新一次。

- **谁回话**：主人最后一句之后没有咕嘎发言、且这条还没答过，群信使才叫醒该回的人。主人连发多条只回一次；咕嘎自己的发言不会触发下一轮（不死循环）；进程重启也不重复回。
- **点名**：主人在页面上点头像 = 只叫这几位；话里叫了名字 = 只叫那位；都没有 = 在线的都回。
- **代发标记**：三号（WorkBuddy）、四号（LightVela）没有直接发言通道，由我替它们贴——帖子上标「代发」，话必须是它们自己说的，我既不改写也不把它们的记忆抄到自己这边。
- **预算**：三号每答一句要吃它平台一次调用额度，所以排最后说。
- **手机版六号页 `/m6.html`**：主界面就是对话，顶栏点开看那台机器的连接信息（名字 / 系统 / 用户 / 权限 / 端口 / 在线）+ 「断开并撤销」。

### 2.8 远程操作（第③ tab）

**两类机器，两条路：**

- **自有机器**（五号 ASUS 笔记本）：机器主动反向连到服务器，我这边 `ssh 别名` 就能落到那台机器上执行命令。接新自有机器有向导脚本（自动推荐端口、生成公钥、装成计划任务、断线自动重连）。
- **别人的机器**（咕嘎六号）：对方打开 `https://join.dqmguga.site/join.html`，输连接密码 → 点同意 → 那台机器连进来，我在页面上替它操作。**关掉网页约 2 分钟后自动断开**；页面上「断开并撤销」一点就真断（隧道由目标机自己拆，十几秒内干净）。

**确认门**：远程执行一律先判风险。含 shell 元字符一律算危险；否则查只读白名单，查不到的默认拒绝。写操作与危险命令必须先经主人确认；对方只读模式下的写/危险命令直接 403。所有命令先进对方本机的审计日志再执行，服务器侧另存一份审计流水。

**每台机器有自己的会话与记忆**（专属记忆文件 + 自己那段对话），只有总记忆文档共享，实时对话不共享。服务器本身不列入机器列表——要操作服务器直接找管家。

### 2.9 热点侦察（咕嘎斥候）

每天 22:00 扫微博、知乎、百度、B站、头条五个平台 + 中新网国内外两路，取各自榜首与大事，写一份日报落盘，并把要点发进咕嘎群。主线是「值得留意的连续性」——同一件事连着几天在榜、某条线突然消失，都会记一句。深挖单个话题也是它的活。

### 2.10 飞书同步（经咕嘎四号）

本机没接任何消息平台，主人的手机出口是四号（腾讯轻量云上的托管 Hermes，连着飞书 DM）。

- **早晚报照抄**：我生产、它播报、一字不改。它那两个定时任务已改成纯脚本任务（读我推过去的那份文本原样投递），不经过模型，所以不会被改写。时间顺序卡死：我的 08:00 / 22:00 先跑，推送到 08:04–08:34 / 22:04–22:34，它 08:06 / 22:09 才发。
- **滤掉的东西**：`::sysinfo` / `::options` 这类只有网页认的行和末尾蓝点，在过桥前就清掉。
- **验证**：不看任务列表里那个 ok（那只代表脚本跑完了），要查投递结果是不是真的「已投递」。

### 2.14 记忆与知识（能力的底座）

这套系统的价值一半在记忆。分四层，各归其位：

| 层 | 放什么 | 位置 |
| --- | --- | --- |
| 常驻记忆 | 跨会话必须知道的身份与操控规矩 | 内核记忆（每轮都注入） |
| 知识分区 | 技能与流程、每个工程一份、价值观、饮食、想法 | `knowledge/` 一棵树 |
| 技能 | 可复用的做法与踩坑（按需加载） | `skills/` |
| 待办与提案 | 待办真源、待批提案、批准清单 | 单一文件，脚本读写 |

另外「远程操作」那条线是**独立分身**：空记忆、共用技能，看得到工具但看不到管家的生活记忆。这样别人的机器接进来，也碰不到主人的私事。

### 2.15 安全与门卫

- 整站在门卫后面：没登录一律跳登录页。登录换一个**签名 cookie**。
- 两个账号：一个长期免再验证（10 年），一个会话级（关浏览器即失效，页面也不让浏览器存账密）。
- 密码框不显示原点：输入框里是每次击键重掷的随机字符，真密码只存在页面变量里。
- 给外人的只有 `join` 那一页，免密但只放行接入必需的几条接口，其余一律 404；带密码、带密钥管理的接口绝不出现在公网白名单里。
- 域名、端口、反代这类基础设施改动，我必须先问主人再动（有过一次中断的教训）。

## 四、一路是怎么优化的

按主题讲，不按流水账。每条都是「原来的问题 → 改成了什么」。

### 4.1 访问方式：从「双击 .bat 开隧道」到「公网 + 门卫」

最初每次用都要在电脑上双击一个隧道脚本，手机没法用，出门就等于失联。

- 备案通过后上了 `dqmguga.site`，整站挂到公网，手机随时能进。
- 认证从浏览器原生弹窗（basic_auth）换成自家门卫：签名 cookie、双账号、密码框不回显。原因是原生弹窗丑且行为不受控（登出、缓存、跨设备体验都差）。
- 公网可达性只认**外部视角**：本机 curl 自己的公网 IP 会 hairpin 超时（腾讯云的 NAT 不回环），看着像挂了其实没挂。改用外部探测服务测，才查出真实原因是云上防火墙没放 443——本机防火墙早放行了，但从没有外部包到过那个端口。

### 4.2 界面：从一个长页面到一套壳

- 从单页聊天，长成四 tab（管家 / 编码 / 远程连接 / 站点），再分出手机会话版、六号手机版、群页、规划页。
- 加新 tab 有个硬约束：切 tab 时管家那块聊天面板要么搬过去要么清空，只有特定类型的 tab 才不会触发清空。所以新页面一律做成「安全类型」，避免把正在进行的一段对话弄丢。
- 手机端语音输入踩到底：安卓原生语音识别把声音送到境外服务器，这条网络在国内根本走不通。前端怎么改都没用——要修只能把转写搬回自家服务器，方案已呈给主人、尚未开工（现状如实标注在功能文档里）。
- 图片显示：聊天走的那条通道不认贴图标签，于是改成「图放静态目录 + 给可点链接」，比嵌进消息里还稳。

### 4.3 记忆：从一个大文件到知识分区

早期所有记忆挤在一份文件里，越写越乱、还容易超预算。现在四层分工：常驻记忆只放「每轮都必须知道」的身份与操控规矩；流程与踩坑进技能（按需加载，不占常驻预算）；每个工程一份项目文档；主人的价值观、饮食、想法各自独立成文。

配套一条硬规矩：**完成任务时学到的东西，写进对应技能或项目文档，而不是往常驻记忆里堆**。所以这套系统的常驻记忆一直很小，但活儿越干越顺。

### 4.4 定时任务：从「让模型写」到「让脚本跑」

早先每个定时任务都是一次模型调用：费 token、慢、还可能改写原文（早晚报被润色过，主人不喜欢）。后来一刀切开：

- **要判断的**（早报、晚报、周复盘）留给人格化的 agent 任务；
- **照抄就够了**（晚安提醒、到点提醒、夜间自检、简报过桥）改成纯脚本任务，脚本输出直接投递，不经过模型——零成本、一字不改。

### 4.5 推送：从「即时打扰」到「打开就看到」

主人明确要求不必准时推。于是所有定时输出落本地收件箱，界面打开时统一领取。手机那边只留早晚报一条同步通道，而且是单向照抄（我做内容、四号当喇叭），时间顺序卡死，防止发了空的内容。

### 4.6 夜间自动化：从「自己找活干」到「批准清单制」

最初夜间会自己挑活做，风险是自作主张。现在：01:00 只负责找候选写进想法池 → 晚报用选项呈给主人 → 主人在批准清单里点头 → 02:00 只做清单里的。清单为空就什么都不做。这条是从「能力」退回「边界」的一次优化。

### 4.7 远程接入：从「我告诉主人一堆步骤」到「一键脚本 + 网页授权」

自有机器接入的脚本一个坑一个坑磨出来（十六类，全记在流程文档里）：主机名必须写 localhost 而不是 127.0.0.1、PowerShell 里变量紧跟冒号会被当成作用域限定、公钥文件权限必须让隧道用户可读、Windows 下中文脚本必须 UTF-8 带 BOM、计划任务里得用 ssh 绝对路径、执行策略被组策略锁死时任何加载 .ps1 的做法都会失败（改成把代码内联成 base64）……

给别人的机器则做了网页授权：对方不用装任何东西，打开网页点同意就进来。几个设计取舍：

- 隧道公钥只写进内存盘（tmpfs），机器重启即空——**无痕**，不用 sudo、不放宽服务安全设置。
- 凭证一次性、10 分钟过期；连上就作废，重连必须重新打开页面输密码。
- 心跳续租 130 秒，关掉页面约 2 分钟服务器撤销会话，真正拆隧道的是目标机（服务器杀不掉受限账户下的进程）。
- 服务器判断「会话还在不在」只在服务器明确回「没了」时才算断，网络抖一下不会误杀。

### 4.8 内存：4 核 4G 上的瘦身

内存常年只剩 1.4G，交换空间一度见底。做法三条：交换空间专门的巡逻任务（超过阈值才出声，顺手清残留浏览器会话）；每半小时清浏览器残留进程；把重活（大依赖、重构建、批量下载、GitHub 直连）外派给四号那台 7.6G 的机器，结果取回来。

### 4.9 群聊：从「都是我说」到「各说各的」

群里先是只有我说话，主人要的是「每个咕嘎是它自己」。于是：三号用常驻浏览器在它自己的会话里打字取回原话；四号走它的 exec 通道跑一轮；每条都标「代发」；点名叫谁就只叫谁；回话的条件卡死（主人最后一条之后没人说过、且这条没答过）——避免几个人抢话、避免死循环。

### 4.10 可靠性：每次改动都留退路

- 改任何前端文件先备份，改完用无头浏览器**真跑一遍**看渲染出的页面，不靠「看着像对」。
- 有风险的改动配一键还原脚本（反代配置、门卫、接入页、段位判定都各有一套）。
- 基础设施（反代 / 域名 / 端口 / DNS）改动必须先问主人——这条是拿一次真实中断换来的。
- 单文件挂载的反代配置改了要**重启容器**才生效，热载会静默地什么都不做（这条坑得记死）。

## 五、边界（明确不做的）

- 不做多用户、不做对外分享（接入页除外）。
- 不主动对外推送打扰主人；不自行启动主人没批准的新工程。
- 不替主人点任何第三方授权（GitHub / Notion / 腾讯文档这类 OAuth 得他本人点）。
- 不碰四号的套餐、支付、账号与实名设置。
- 编码项目本身归零号，管家不越界。
- 密码、密钥、cookie 不写进任何文档、不进群、不进记忆。
