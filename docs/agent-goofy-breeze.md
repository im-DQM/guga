# 私人云端 Agent 管家 + 编码终端 — 完整计划（简化版）

## Context（为什么做这个）

三样东西，合在自己的一套云端上：

1. **常驻的私人 agent 管家**——记得你、随时对话（零安装），管日程、提醒、杂事。
2. **专业编码环境**——Claude Code + 自研网页终端外壳（有 diff、有权限确认）。
3. **远程操作电脑**（命令行级、尽量零安装）——对着管家说，它去操作你任意台机器完成日常任务；涉及复杂设计问题时，调 Claude Code 当参谋。

都要：**自建、单用户、国产模型可切换、数据在自己手里**。

> 关键简化：不做自研 agent、不做富界面。**Hermes 和 Claude Code 都是现成的 TUI 程序**，只要把它们的**终端外壳换成网页终端**即可——"换壳不换引擎"。

## 核心决策（已锁定）

| 项 | 决定 |
|---|---|
| 形态 | **一个网页终端网关**，里面跑两个会话：`hermes`（管家）、`claude`（编码） |
| 实现 | **`ttyd` + `tmux` + Caddy**——几乎零开发 |
| 管家内核 | **Hermes Agent**（开源 MIT，自带记忆/技能/定时） |
| 编码内核 | **Claude Code 原样用**，只把终端外壳换成网页终端 |
| 远程操作（功能 3） | **Hermes（backend=local）用 `ssh <别名>` 够到目标机**，支持多台；目标机**零 agent**，只要 SSH 可达 |
| 模型 | **国产**（GLM/Kimi/DeepSeek…），经环境变量配置，API 后配 |
| 服务器 | **一台国内大陆**轻量服务器，**4核4G** 起步 |
| 代码托管 | **Gitea** 自托管 |
| 用户 | 单用户 |

```
              │        Caddy            │  HTTPS + 自动证书 + 认证门槛 + 反代
              └──┬──────────┬───────┬──┘
    term.<域名>  │          │       │ git.<域名>
         ┌───────▼──────┐   │   ┌───▼──────────┐
         │  ttyd 终端网关 │   │   │   Gitea      │
         │  ├ tmux:claude │   │   │ 自托管 git    │
         │  └ tmux:hermes │   │   └───┬──────────┘
         └───────┬───────┘   │       │
                 │           │       │
       ┌─────────▼───┐  ┌────▼────┐  ▼
       │ Claude Code │  │ Hermes  │ /data/gitea
       │ (编码会话)   │  │(管家会话)│

              ▼              ▼

```

**核心**：你不写 agent、不写界面。你搭的是**一个能安全地把终端搬到网页的网关**，外加两个现成 CLI。

## 组件

### 1. 网页终端网关（本项目唯一自研，且很薄）
- **`ttyd`**：把命令暴露成网页终端；每个会话挂到一个 **`tmux`** 会话上（刷新/掉线不丢）
- 前端就是 ttyd 自带的 xterm.js 页面；**无需自写**
- Caddy 在前面做 HTTPS + **认证门槛**
- 备选：`Wetty`，或自写 node-pty + xterm.js（需要更细的控制时）

### 2. Claude Code（编码会话）
- 服务器上装 `claude` CLI；在 `/data/workspaces/<repo>` 里跑
- **原样使用其 TUI**——diff、权限提示都在 TUI 内，你在网页终端里直接操作
- 模型经环境变量指向国产端点

### 3. Hermes 管家（管家会话）
- 服务器上装 `hermes`；在 tmux 里常驻
- 记忆、技能、定时任务全用它自带的
- 同样的网页终端里操作（TUI）
- （可选将来换成更漂亮的聊天界面：Hermes 有 OpenAI 兼容 API server，可接 Open WebUI——非必须）

### 4. Gitea（自托管代码）
- 单用户、SQLite 后端；**关闭公开注册**（`DISABLE_REGISTRATION=true`）
- 跑在 `git.<域名>`；可选 push mirror 到 GitHub 备份

### 5. Caddy
- HTTPS 终止、自动 Let's Encrypt 证书、按域名反代、**认证门槛**

### 6. 模型接入
- `claude` 与 `hermes` 都走国产模型：`ANTHROPIC_BASE_URL` 指向厂商 Anthropic 兼容端点 + `ANTHROPIC_DEFAULT_*_MODEL`
- 用 **cc-switch** 管理多供应商（同时支持 Claude Code 和 Hermes）
- **无自建改写网关**

### 7. 认证与安全（**本方案的头号风险**）
> 你在公网暴露的是一个**终端**；Claude Code 能执行 bash，等于**暴露了一个 shell**。
- 强认证：密码（argon2）+ **TOTP**；**不能**只依赖 ttyd 的 basic auth
- 全站 HTTPS；登录限流；fail2ban / 防爆破
- 考虑：终端只允许启动白名单命令（`claude` / `hermes`），缩小爆炸半径
- 可选加固：把站点挡在 Cloudflare Access 或自建 forward-auth 之后

### 8. 服务器与备案
- **4核4G** 起步 + **2–4G swap** 兜底；系统盘 ≥100G SSD；Ubuntu 24.04 + Docker
- **ICP 备案**（大陆必经，1–3 周，**第一件事启动**）：买实名域名 → 买大陆服务器（拿备案服务号）→ 提交备案 → 等待期用 IP + 非标端口开发 → 通过后域名解析 + Caddy 自动签 HTTPS → 30 日内公安备案

## 功能 3 · 远程操作目标机（命令行级、尽量零安装）

- **主脑**：云端 Hermes，`terminal.backend=local`；它自己用 **`ssh <别名> "命令"`** 够到各目标机 → 支持**多台**，且**绕开"Hermes 一次只能一个 backend"**的限制。配 SSH `ControlMaster` 复用连接提速度。
- **目标机要求**：只需 **SSH 可达**（Linux/macOS 自带；Windows 开"OpenSSH 服务器"）。NAT 后用系统自带的 **`ssh -R` 反向隧道**主动外连 + `autossh` 保活。**目标机零 agent 安装。**
- **交互**：对着管家说自然语言，命令落到目标机执行。
- **复杂设计问题**：调**云端 Claude Code** 当参谋（产出方案/脚本/命令），再由管家送回目标机执行 → **仍零安装**。
- **硬边界**：这是"**命令行级**"。若要在目标机上**交互式改代码/调试**，才需在那台机装 Claude Code。**锁死、不能开 SSH 也挂不了隧道的机器（如某些公司机）够不到**——物理边界，无解。

## 采购与磁盘策略（2026-10-09 定）

**镜像**：选 **`Ubuntu24.04-Docker29`**（Ubuntu 24.04 + 预装 Docker，省一步）。**不用**腾讯的 Hermes / OpenClaw 应用镜像——那是它自家的托管式流程，跟你自定的架构不搭。

**加购**：**一项都不买**。COS / CDN / 企业网盘 / 对象存储都不需要；**对象存储不能挂载，补不了系统盘**。

**规格**：**4核4G + swap** 起步。**40G 系统盘是短板**——能选大盘就选大盘（≥80G）；只有 40G 就先跑阶段 1。轻量系统盘**不能外挂数据盘**，只能换套餐。

**磁盘策略（关键，让 40G 够用）**：
- **代码托管用本地 Gitea**：日常推/拉走**内网**，秒级、不耗公网带宽；再配 **Gitea → GitHub push-mirror** 做**异地备份**（免费）。GitHub 只当保险柜，不当日常拉取源。
- **工作区用完即清**：交付后删 `node_modules` + 构建产物（**保留代码分=省去重拉**），或整仓删、下次从 Gitea 重拉。`node_modules` 不在 git 里，正是最占地方且会无限涨的部分。
- **铁律**：**先 commit + push 再删**；`.env`(密钥) / 本地数据库 / 生成物**不在 git 里**，删了就没——单独备份。
- **效果**：磁盘稳定在 ~13–29G，**不随项目数增长** → 40G 可用。

## 实施顺序

**阶段 0 · 地基**：域名 + 服务器 → **提交备案** → 装 Docker + Caddy + Gitea + ttyd + tmux。
**阶段 1 · 终端网关 + 管家**（最快见效）：配 ttyd + tmux + 认证门槛 → 网页里开出 `hermes` 会话 → 配国产模型 → 能对话、有记忆、能定时。
**阶段 2 · 编码会话**：装 `claude` CLI → 网页里开出 `claude` 会话 → Gitea 建仓 → 让 Claude Code 在 workspace 里 clone/改码/diff/push。
**阶段 3 · 打磨**：tmux 会话管理、备份、手机端优化、移动端快捷键。

## 主要风险

1. **安全——公网暴露终端**（最高）：必须强认证 + HTTPS + 防爆破；否则等于把 shell 挂在网上。
2. **TUI 在浏览器终端里的兼容性**：鼠标、resize、`Shift+Enter`、闪烁——**第一天就测**；不行回退到"SDK + 自研富界面"。
3. **手机体验**：网页终端在手机上一般（小屏 + 软键盘）。
4. **国产模型的编码手感**：不如 Claude；小任务先验证，模型可换。
5. **备案时间**：1–3 周，只能并行开发化解。
6. **功能 3 的边界**：零安装仍要求目标机"能开 SSH 或挂隧道"；不能开的机器够不到。要在目标机**交互式改码**才需装 Claude Code。

## 验证方式

- **管家**：手机打开网页终端 → 跟 hermes 对话 → 记一件事 → 隔天它还记着 → 定时任务按时触发。
- **编码**：网页终端里跑 `claude` → 在 Gitea 仓库上 clone → 改代码 → **TUI 里看到 diff** → 权限提示可交互 → push 回 Gitea → **Gitea 网页看到新提交**。
- **集成访问**：对着管家说"在我的笔记本上做 X" → 命令经 SSH 落到笔记本并生效，且**笔记本未装任何 agent**；断掉隧道再连，`autossh` 自动恢复。
- **安全**：未认证访问被挡；错误密码连错 N 次被锁；TOTP 生效；断线后 tmux 会话仍在。
- **资源**：`docker stats` / `htop` 观察峰值，尤其编码 + `npm install` 时；不够升 8G。

## 入口页（三模式 Hub）与部署现状（2026-10-09）

**目标**：一个入口页，进去是**三种模式**——① 个人管家 ② 编码 ③ 本机操作；选对应进入对应 AI；**第三个（本机操作）暂不开放**（灰显）。

**已部署**（服务器 `/home/ubuntu/stack/`）：
- `hub/index.html` —— 静态入口页（三卡片），Caddy 托管在 `/`
- `docker-compose.yml` —— `caddy` + `gitea` 两服务
- `Caddyfile` —— `/hermes*`→`7681`、`/claude*`→`7682`、其余走静态文件
- 状态：入口页 **200 ✓**；但 `/hermes` `/claude` **反代 502 ✗**

**502 根因**：Caddy 在 bridge 网络里经 docker 网关（`172.17.0.1`）访问宿主机 ttyd，被 **ufw 默认拒绝**（Caddy 日志：`dial tcp 172.17.0.1:7681: i/o timeout`）。

**修法（推荐）**：Caddy 改成 **`network_mode: host`**，Caddyfile 站点地址改 `http://127.0.0.1:8080`，反代目标改 **`127.0.0.1:7681` / `127.0.0.1:7682`**，去掉 `ports:` 映射。
- 绕开"docker → 宿主机"的 ufw 拦截；
- **未来接域名可直接绑 80/443**，同一容器不用改。
- 备选：给 ufw 放行 docker 网段（`sudo ufw allow from 172.16.0.0/12`）——更快但更糙。

**本机侧**：`~/.ssh/config` 的 `dqm` 增加 `LocalForward 8080 localhost:8080`；更新 `D:\dqm-claude\启动隧道.bat`。**入口地址改为 `http://localhost:8080/`**（Gitea 仍走 `localhost:3000`）。

**验证**：浏览器打开 `http://localhost:8080/` → 见三张卡 → 点「个人管家」「编码」能进且可交互 → 「本机操作」灰显不可点。

**待办**：Caddy 加**认证门槛**（密码+TOTP）——现在入口页/终端**没有任何认证**，只靠"隧道只在你本机"护着；一旦对外（域名）必须补上（对齐「组件 7 认证与安全」）。

> 注：本节的"裸终端入口页"为**临时形态**，将被下一节的**自定义交互外壳**取代（ttyd 会话保留作直连/回退）。

## 交互外壳（自定义 UI）— 设计（2026-10-09 定）

**目标**：把"裸终端 hub"换成**自定义外壳**——打开网页**直接进管家**；**顶部**切换 **管家 / 编码 / 本机操作**。

**形态**：
- 打开 → 默认 **管家**（自建聊天 UI，**仿 Open WebUI**）
- **顶部**切换：**编码** / **本机操作**（灰显占位）
- **二者同时运行**：管家（`hermes-api` 服务）与编码（`code-server` 服务）**都常驻**；切换只切**视图、不中断**——外壳里两个视图**都保持挂载**（切回来会话/状态还在）
- 认证：**稍后**（先不做）

### 管家模式 = 自建 chat UI（**非终端**）
- **数据源**：**Hermes 的 OpenAI 兼容 API server**（`API_SERVER_ENABLED=true`，端口 **8642**，**SSE 流** + `hermes.tool.progress` 工具事件）
- **UI**：轻量自建（React 或原生），渲染**流式回复** + **工具进度**；会话续接用 `/v1/responses`（`previous_response_id` 或命名会话）
- **密钥不进浏览器**：前端调 `/api/hermes/*`，由 **Caddy 注入** `Authorization: Bearer <key>` 转发到 `127.0.0.1:8642`

### 编码模式 = `code-server`（VS Code Web）
- ✅ 采用**方案甲**：`code-server` 一体提供 **文件树 + 编辑器 + 集成终端**；**在集成终端里跑 `claude`**（diff/权限都在里面）——省掉自建分栏与自建编辑器
- 工作区 = `/home/ubuntu/workspace`
- 外观：先用 **VS Code 主题/配色/字体**（**方案 A，零开发**）
- 因为 code-server 是完整应用：外壳"编码"页**默认 iframe 嵌入**（保外壳统一）；若太重，退化为**整页跳转**（caddy 下 `/code` 或子域）

### 本机操作
- 灰显占位，暂不实现。

### 部署（服务器）
- `hermes-api.service`（systemd）：`hermes gateway` 常驻 **8642**（需在 `~/.hermes/.env` 开 `API_SERVER_ENABLED`）
- `code-server.service`（systemd）：绑定 `127.0.0.1:8081`
- **外壳前端**：一个静态小应用（或 React 构建产物），Caddy 托管在 `/`
- **Caddyfile**：`/` → 外壳；`/api/hermes/*` → `127.0.0.1:8642`（注入 key）；`/code/*`（或子域）→ `127.0.0.1:8081`
- 本机隧道新增 **8081** 转发（code-server）

### 资源
- `code-server` 约 **300–500MB**；**4G 会紧张**（同时跑 Hermes+claude+VS Code），编码时注意；不够升 **8G**。

### 验证
- 打开 `http://localhost:8080/` → **默认进管家聊天**，能**流式**对话、看到**工具进度**；切到**编码** → VS Code 出**文件树**，**集成终端里 `claude` 能跑**；切回管家，**会话还在**。

### 后续（方案 B）
- 给终端做**自定义皮肤**（ttyd `--index` 自定义 HTML/CSS，或自绘 xterm.js），与 code-server **分栏**。

## 编码页换壳（2026-10-10 实现）

**目标**：把「编码」页从"整页 VS Code"改成——左深色 VS Code ＋ 右上 claude 终端 ＋ 右下 shell 终端；claude 可多开 / 切换 / 删除。

**组件**
- `~/stack/term/ttyd-run.sh`：参数化 ttyd 启动器（`TTYD_ACCENT` / `TTYD_GOLD`）
  - claude 终端：蓝 `#4C8DFF` ＋ 金 `#E4C57E`；shell 终端：靛紫 `#7C8CFF`
- **`guga-term-api`**（`~/stack/term/term-api.py`，`:8791`）：tmux 窗口管理
  - `GET /list` `/new` `/select?i=` `/kill?i=`（Caddy `handle_path /api/term/*`）
  - ⚠️ 会话目标必须写显式 `claude:`——窗口名也叫 `claude`，否则 `-t claude` 会解析到那个窗口
- `~/.tmux.conf`：深色状态栏 ＋ `mouse on`（滚轮看历史）＋ `history-limit 20000`
- `~/.local/share/code-server/User/settings.json`：VS Code 深色主题 + 自定义配色；systemd drop-in 加 `~/workspace` 参数默认打开工作区
