# 功能③ · 远程操作 —— 实现计划

## Context（为什么做 / 现状 / 目标）

项目是自建的私人云端 Agent，跑在腾讯云 `106.55.38.108`（Ubuntu 24.04，4核4G，浏览器访问）。已有两模块：**管家「咕嘎一号」**（内核 Hermes Agent）+ **编码**（code-server + 多开 claude 终端）。第三模块「本机操作」目前只是 hub 里一个灰显 tab + 占位 div（`~/stack/hub/index.html:292` 的 `disabled`、`:352` 的 `#view-local`），完全未动工。

本计划实现**功能③：在授权前提下远程操作其他电脑**。用户已敲定的定义：

| 维度 | 定 |
|---|---|
| 目的 | 远程操作其他电脑；**完整 shell 级**能力，文件操作为主场景 |
| 目标机 | ① 用户自己的机器（如 Windows 笔记本 ASUS）② 别人的机器 |
| 接入授权 | 自有：接入一次、**长期可用**；他人：**每次接入**由对方在其**浏览器同意页**（标题「**咕嘎一号请求访问**」）授权 |
| 操作授权 | 每次操作**用户自己**点头即可（不再麻烦对方） |
| 数据留存 | 自有：可留；**他人：服务器一点都不留**（别名 / 密钥 / 日志 / 会话全不落盘），对其操作记录**写在那台机器本地** |
| 交互 | 聊天自然语言 **+** 「本机操作」管理页，**两者都要** |

**架构信条（换壳不换引擎）**：不改 Hermes 内核、不改 Claude Code；一切靠 `ssh` + Hermes 技能 + 现成 ttyd/tmux/小服务范式。

- Hermes 保持 `terminal.backend=local`（裸 bash，无命令白名单，`ssh <别名> "命令"` 不会被拦）→ **多主机靠 SSH 别名实现**，绕开 Hermes「全局只有一个 terminal backend」的限制。
- **不用** Hermes 内置 ssh backend：它是单主机直连，且会**反向把 `~/.hermes` 同步到目标机**（`~/.hermes/hermes-agent/tools/environments/ssh.py:82-88`），与「目标机零安装」冲突。
- **不注册**自定义 terminal backend（`agent/terminal_env_registry.py` 虽留插件口，但全局单 backend、内置名保留，不值得）。

**当前最大缺口**：服务器 `~/.ssh/` 只有一把 Windows 登录用 `authorized_keys`，**没有私钥 / config / known_hosts** → 现在 `ssh` 连 localhost 都认证失败。功能③的第一件事就是补这个。

## 两层授权模型（本设计的骨架）

```
接入层（谁的机器谁说了算）
  自有机器 → 接入一次，长期可用（公钥常驻 authorized_keys）
  他人机器 → 每次接入都要机主授权（限时 key / 会话级，用完即撤）
        │
        ▼
操作层（用户自己说了算）
  自有机器 → 只读自动放行；写 / 危险 → 用户确认
  他人机器 → 一律用户确认（对齐「每次操作我自己授权」）
```

## 核心组件

### 1. 服务器 SSH 基建

**两把职责分离的密钥**（都用 ed25519、无口令，供无人值守）：
```bash
ssh-keygen -t ed25519 -f ~/.ssh/guga_ops    -C "guga-ops@cloud"    -N ""  # 服务器主动连目标机
mkdir -p ~/.ssh/control ~/.ssh/config.d && chmod 700 ~/.ssh/control
```
- **`guga_ops`**：服务器 → 目标机。**公钥**分发到各目标机 `authorized_keys`。
- **隧道密钥**：目标机 → 服务器（反向用）。**每台目标机一把独立**（隔离、可单独吊销）：私钥留在那台目标机，**公钥**进服务器 `~/.ssh/authorized_keys`，并加限制项（见 §4）。

**`~/.ssh/config`**（连接复用 + 存活 + 主机 key 策略）：
```sshconfig
Host *
  ServerAliveInterval 30
  ServerAliveCountMax 3
  TCPKeepAlive yes
  ControlMaster auto
  ControlPath ~/.ssh/control/%C
  ControlPersist 300
  StrictHostKeyChecking accept-new

Include ~/.ssh/config.d/guga-remote   # 由 remote-api 从 hosts.json 生成，别手改
```
`ControlMaster/ControlPersist` 是连接复用（内置 ssh backend 同款做法，见 `tools/environments/ssh.py:114-126` 可参照）。

**known_hosts**：自有主机接入时人工核一次指纹后预置（反连端口用 `ssh-keyscan -p 22022 127.0.0.1 >> ~/.ssh/known_hosts`）；他人主机靠 `accept-new`，会话结束可选 `ssh-keygen -R <host>` 清痕。

### 2. 主机注册表（单一真相）

**`~/stack/remote/hosts.json`** 为真相（**只存自有机器**），`remote-api` 据此生成 `~/.ssh/config.d/guga-remote`（主机要在聊天与 UI 双入口增删）：
```json
{
  "win-asus": {"name":"我的 ASUS 笔记本","kind":"own","os":"windows",
               "via":"reverse","listen_port":22022,"user":"ubuntu"}
}
```
> **guest 机器一律不写入** hosts.json——其别名 / 端口 / 临时密钥只存在于内存或临时目录，用完即弃（见 §3.2「guest 无痕」）。
生成片段：
```sshconfig
# GENERATED by remote-api.py — 别手改
Host win-asus
  HostName 127.0.0.1
  Port 22022
  User ubuntu
  IdentityFile ~/.ssh/guga_ops
  IdentitiesOnly yes
```
**Hermes 怎么知道有哪些主机**：不加新机制——技能里写明「真相在 `~/stack/remote/hosts.json`，需要时 `cat`」，因为 ssh 别名是生成的，`ssh <别名>` 天然可用。

### 3. 目标机接入（两档）

#### 3.1 自有机器（长期可用）

- **Linux/Mac**：目标机执行
  ```bash
  mkdir -p ~/.ssh && chmod 700 ~/.ssh
  echo "<guga_ops 公钥>" >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys
  sudo systemctl enable --now ssh     # Debian 系；macOS 用 系统设置→共享→远程登录
  ```
- **Windows（管理员 PowerShell，完整脚本）**：
  ```powershell
  # 1) 装 OpenSSH Server 可选功能（Win10 1809+ 自带能力，无需下载）
  Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
  # 2) 开机自启 + 启动
  Set-Service -Name sshd -StartupType Automatic ; Start-Service sshd
  # 3) 防火墙放行（-Profile Private 更保守；跨网络用 Any）
  New-NetFirewallRule -Name sshd -DisplayName 'OpenSSH Server' -Enabled True `
    -Direction Inbound -Protocol TCP -Action Allow -LocalPort 22 -Profile Any
  # 4) 默认 shell 设为 PowerShell 7（解决 cmd 的引号 / 中文编码坑）
  New-ItemProperty -Path "HKLM:\SOFTWARE\OpenSSH" -Name DefaultShell `
    -Value "C:\Program Files\PowerShell\7\pwsh.exe" -PropertyType String -Force
  ```
  **公钥落位（关键坑）**：
  - 普通账户 → `C:\Users\<u>\.ssh\authorized_keys`
  - **管理员组账户 → `C:\ProgramData\ssh\administrators_authorized_keys`**，且**必须修 ACL**，否则 sshd 直接忽略该文件：
    ```powershell
    $f = "C:\ProgramData\ssh\administrators_authorized_keys"
    Set-Content -Path $f -Value "<guga_ops 公钥>" -Encoding utf8
    icacls.exe $f /inheritance:r /grant "Administrators:F" /grant "SYSTEM:F"
    Restart-Service sshd
    ```
  脚本自动判断账户是否属管理员组，**两条落位都覆盖**。
  **编码/引号规则（写进技能）**：统一默认 shell = pwsh 后用 `ssh win-asus "Get-ChildItem C:\Users"`；**远端命令尽量不含中文字符串**，必须用时先 `chcp 65001`；嵌套引号外层双内层单，复杂命令用 `-EncodedCommand`（base64）绕开转义。

#### 3.2 他人的机器（每次接入需对方授权）

**形态：对方在浏览器里点同意 + 一次性命令 + 临时反向通道。** 本轮只设计，**备案 + HTTPS 就绪后落地**（见下方「依赖」）。

1. 用户对咕嘎说「要操作张三的机器」→ 咕嘎生成一次授权请求，产出链接 `https://<域名>/join/<一次性token>`。
2. 对方在**他自己的电脑浏览器**里打开该链接 → 看到 **「咕嘎一号请求访问」**（对方看到的是咕嘎，不是用户本人）+ 说明（能做什么、多久）→ 点【同意】。
3. 页面随即给出**一条一次性命令**（内含一次性密钥）→ 对方在自己电脑上跑一下 → 建立到服务器的**临时反向通道**。
4. 服务器侧：临时通道 + 临时密钥**只存在于内存/临时目录，绝不落盘**；操作记录**写回对方机器本地**（见 §5）。
5. **结束**（用户点断开 / 对方撤销 / token 过期）→ 通道与临时密钥**即刻销毁，服务器无痕**。

**「guest 无痕」原则**：服务器对 guest 机器不保留**任何**持久化数据——别名、端口、密钥、日志、会话状态统统不落盘；每次接入都是全新临时通道。因此 §1 的隧道限制键 / §2 的 hosts.json **都不接纳 guest**，键写进临时的 `AuthorizedKeysFile` / `config.d` 片段，随会话销毁。

> **依赖（前置）**：同意页要求对方浏览器能访问服务器 → **必须等 备案 + 域名 + HTTPS + 密码/TOTP 就绪**（P0）。本轮不做，仅设计。

### 4. NAT 反向隧道

自有机器多在 NAT 后、公网 IP 会变 → 由**目标机主动外连**服务器并请求反向转发（`ssh -R`），服务器只监听回环端口。

**目标机侧命令**：
```bash
ssh -N -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -o ExitOnForwardFailure=yes \
    -o StrictHostKeyChecking=accept-new -i <本机隧道私钥> \
    -R 127.0.0.1:22022:localhost:22 ubuntu@106.55.38.108
```
- 服务器 sshd 现状 `AllowTcpForwarding` 默认 yes、`GatewayPorts no` → 反向监听**只绑回环**，正是想要的姿态，**无需改 sshd_config**。
- 端口分配：回环高位端口，**每主机一个**（22022、22023…），写入 `hosts.json.listen_port`。

**服务器 `~/.ssh/authorized_keys` 里给隧道公钥的限制项**（把该 key 锁死到"只暴露一个回环端口"）：
```
restrict,port-forwarding,permitlisten="127.0.0.1:22022" ssh-ed25519 AAAA... guga-tunnel-win-asus
```

**保活（跨平台统一用"循环/supervisor"，不引入 autossh）**：
- **Windows**：计划任务 + PowerShell 循环（零第三方）：
  ```powershell
  # C:\guga\keep-tunnel.ps1
  while ($true) {
    ssh -N -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -o ExitOnForwardFailure=yes `
        -o StrictHostKeyChecking=accept-new -i "$env:USERPROFILE\.ssh\guga_tunnel" `
        -R 127.0.0.1:22022:localhost:22 ubuntu@106.55.38.108
    Start-Sleep -Seconds 10
  }
  $a = New-ScheduledTaskAction -Execute "pwsh.exe" -Argument "-WindowStyle Hidden -File C:\guga\keep-tunnel.ps1"
  Register-ScheduledTask -TaskName guga-tunnel -Action $a -Trigger (New-ScheduledTaskTrigger -AtLogOn) -RunLevel Highest
  ```
- **Linux**：systemd unit（`Restart=always`）包住同样的 `ssh -N -R`。

**「零安装」与「保活要留东西」的张力（明确告知）**：零 agent ≠ 零配置。要稳定长期可用，目标机至少留**一个保活物**（Windows 一个计划任务 + 一个 ps1 + 一份隧道私钥；Linux 一个 unit）——但都由系统自带 ssh 驱动，**不装我们的软件**。若坚持真零残留，只能"每次手工开隧道"，掉线不自恢复。

### 5. 操作层授权（用户自己）

**复用 Hermes 审批门的 UI，自建远端动作确认逻辑**（因为内置门判不了远端载荷：`approval_detection.py:84-111` 的引号掩码会把 `ssh host "rm -rf …"` 的载荷当 DATA 掩掉）。

1. **补齐现有半成品**：网关已能经 SSE 发 `approval.request`（带 `once/session/always/deny`），客户端回调 `POST /v1/runs/{run_id}/approval`（`gateway/platforms/api_server.py:70/86`）；但 hub **只渲染成一行提示、没按钮没回提交**（`index.html:609`）。→ 改成渲染 `choices` 按钮并回提交，服务**本地**危险动作的兜底。
2. **自建远端动作门**：`~/stack/remote/guga-remote <host> -- <cmd>` 包装器——先入队到 remote-api，hub 第③页弹「待批」卡；用户点「执行」才真正 `ssh <host> <cmd>`。规则：
   - `own` 机器只读（`ls/cat/git status` 等前缀白名单）→ **自动放行**；
   - `own` 机器写 / 危险 → **确认**；
   - `guest` 机器 → **一律确认**。
3. 技能强制"对 guest 一律走 `guga-remote`"。

**审计归属（对齐「guest 无痕」）**：
- **自有机器**：审计落服务器 `~/stack/remote/audit.log`。
- **guest 机器**：审计**写回对方机器本地**（Linux `~/.guga/audit.log`、Windows `%USERPROFILE%\.guga\audit.log`），由那条临时通道在执行时追加；**服务器不留副本**。

### 6. Hermes 能力（自然语言）—— 只加技能 + 记忆

**新技能** `~/.hermes/skills/devops/remote-ops/SKILL.md`（YAML frontmatter，仿 `autonomous-ai-agents/claude-code/SKILL.md` 写法），内容：
1. **主机清单**：真相 `~/stack/remote/hosts.json`；别名 → 用途 / OS / own|guest。
2. **用法**：`terminal('ssh win-asus "Get-ChildItem C:\\Users"')`；先 `ssh <别名> "echo ok"` 探活。
3. **引号/编码规则**：外层双内层单；Windows 默认 pwsh、避免中文、必要时 `chcp 65001` / `-EncodedCommand`；Linux/Mac 用 `shlex` 风格。
4. **安全规则**：`guest` 机器必须先有接入授权、动作一律走 `guga-remote`；破坏性动作先确认；禁止无人在场跑 guest 动作。
5. **复杂任务调参谋**：用现有 `claude-code` 技能（`claude -p '…' --output-format json --max-turns N`）产方案/脚本，再送回目标机执行 → **仍零安装**。

**记忆**：追加一条到 `~/.hermes/memories/MEMORY.md`（该文件已承载本部署知识）：
> 功能③远程操作：`terminal.backend=local`，用 `ssh <别名>` 够目标机（别名真相 `~/stack/remote/hosts.json`，ssh 片段 `~/.ssh/config.d/guga-remote` 由 remote-api 生成）。guest 机器动作一律先经 `guga-remote` 确认；复杂任务调 claude-code 技能当参谋。技能：`~/.hermes/skills/devops/remote-ops`。

### 7. 「本机操作」页面（第③页）—— P2 详细设计

**目标**：把远程操作搬进 hub 第三 tab。**命令框 + 机器列表**；**只读直接跑、写/危险先确认**；本轮**不做**交互式网页终端、文件浏览器、"接入新机器"入口。

**本轮已定（用户拍板）**：① 给 `/api/remote/*` **不加**最小认证（只靠隧道）；② 列表除自有远端机器外**额外加一台「本机（这台服务器）」**（本地执行，同一确认门）；③ **不做**"即便确认也不放行"的灾难硬阻断清单。

#### 7.1 后端 `~/stack/remote/remote-api.py`（新建）
- 标准库 `ThreadingHTTPServer`（一条 30s 的 ssh 不能卡住 `/hosts` 轮询），绑 `127.0.0.1:8792`。
- **无本地 shell**：`subprocess.Popen(["ssh","-o","ConnectTimeout=8","-o","BatchMode=yes","-o","NumberOfPasswordPrompts=0", alias, cmd], shell=False)`——`cmd` 作为单个 argv，只被**远端** shell 解释（这是命令框应有语义）。`host` 只能是 hosts.json 的 key（查表，绝不拼串）。
- 端点（Caddy 用 `handle_path` 剥掉 `/api/remote` 前缀，故服务内路径为裸 `/hosts` 等）：
  | 方法 | 路径 | 说明 |
  |---|---|---|
  | GET | `/hosts` | 列表 + 在线状态。reverse：先探回环端口(1.5s)，再 `ssh … <alias> exit` 冒烟(8s)；**缓存 20s**；多台 `ThreadPoolExecutor` 并发 |
  | POST | `/exec` | `{host,cmd,timeout?}`。只读 → 直接跑并回 `{exit_code,stdout,stderr,duration_ms,truncated,timed_out}`；否则回 `{need_confirm:true,id,verdict,reason,expires_at}`（**不执行**） |
  | POST | `/approve` | `{id,decision}`。`yes`→执行并回结果；`no`→丢弃。**单次使用**（pop） |
- **「本机」**：`/hosts` 里注入一台 `{"alias":"local","name":"本机（这台服务器）","kind":"own","os":"linux","local":true}`；`/exec` 对 `local` 走本地 `subprocess`（同样的 classify 与确认门，不经 ssh）。
- **确认门 `classify(cmd, os) -> (verdict, reason)`**（**安全网，不是安全边界**——hub 无认证）：
  - (a) 含 shell 元字符 → **danger**（POSIX `; | & < > \` $` + 换行；Windows `& | < > %` + 换行）——防组合命令击穿前缀白名单
  - (b) 无元字符 → 首 token 归一化（`basename`、小写、去 `.exe`）查**只读白名单 + 子命令/flag 守卫** → **read**
  - (c) 其余 → **write**；命中显式危险词 → **danger**。**default-deny**：只有明确只读才自动跑
  - 白名单（要点）：POSIX `ls/cat/head/tail/wc/stat/du/df/find/grep/rg/pwd/whoami/id/hostname/uname/uptime/date/free/env/echo/which/ps/ss/ip/…` + `git`(status/log/diff/show/…)、`docker`(ps/images/logs/inspect)。
    Windows `dir/type/hostname/whoami/ipconfig/systeminfo/tasklist/ver/netstat/where/findstr/…` + **`Get-*` cmdlet** 视为只读。
  - 守卫：`find` 含 `-delete/-exec` → 非只读；`tail`/`journalctl` 含 `-f` → 非只读；`docker logs -f` 同理；`wmic` 仅 `get`、`reg` 仅 `query`、`sc` 仅 `query`。**明确排除**：`python3/node/pip/curl/wget/sed -i/tee/dd/rm/mv/cp/chmod/apt/systemctl start|stop|restart/`（一律确认）。
- 待批：内存 `dict` + `Lock` + `secrets.token_hex(4)`；TTL 120s；上限 32；惰性清理。
- **审计** `~/stack/remote/audit.log`（JSONL：`ts/alias/cmd/verdict/decision(auto|approved|denied)/exit_code/duration_ms/…`；**只记大小不记输出正文**）。
- 其他：输出 256KB 截断；超时默认 30s / 上限 120s，`communicate(timeout)` 超时则 `kill()`；`BoundedSemaphore(4)` 限并发 ssh。

#### 7.2 systemd `guga-remote-api.service`
照抄 `guga-term-api.service`（User=ubuntu、Environment=HOME/PATH、Restart=on-failure），**加低成本硬化**：

### 8. 沙箱（服务器侧隔离）—— 本轮硬要求

**目标**：既然允许目标机连进来、又要用它操作，就必须保证——**目标机哪怕被攻陷、或是恶意的，或它返回的内容里藏了 prompt injection（诱导咕嘎在服务器上执行命令），服务器核心都不受影响**。要保护的核心：Hermes / Caddy / Gitea / code-server / `~/.ssh` / 用户其他机器的凭证 / 上层的 `hosts.json`。

**A. 入站隔离**（"别人连进来"能做的极限）
- **独立隧道入口**：单独的 sshd 实例（或同一 sshd 的 `Match` 块）监听专用端口（如 `2222`），只服务隧道用户；`ufw` 仅对该端口放行必要来源；`fail2ban` 盯这个端口。
- **专用系统用户 `tunnel`**：`shell=/usr/sbin/nologin`、无 sudo、无 home 权限、无任何共享目录访问。
- **每主机独立公钥 + 限制项**（服务器 `~/.ssh/authorized_keys` 或 sshd 专用 `AuthorizedKeysFile`）：
  ```
  restrict,port-forwarding,permitlisten="127.0.0.1:22022" ssh-ed25519 AAAA... guga-tunnel-win-asus
  ```
  ⇒ 目标机连进来后**拿不到 shell / pty / agent / X11，也开不了别的端口**，唯一能做的就是把它的 22 暴露到一个回环端口。**被攻陷的极限 = 占一个回环端口。**

**B. 执行隔离**（"操作过程"困在沙箱里）
- 把**持有 ops 私钥、真正发起 `ssh <别名>` 去操作目标机**的执行体，关进一个隔离单元：
  - **方案 1（推荐）：Docker 容器**（本机已有 Docker）——非 root、`--cap-drop=ALL`、`--security-opt no-new-privileges`、只读根文件系统、`--memory`/`--cpus` 上限、**绝不挂 docker socket**、ops 私钥**只读挂载**、出站仅允许到目标机网段。
  - **方案 2（更轻，省 4G 内存）：systemd 硬化**——`ProtectSystem=strict`、`ProtectHome=yes`、`PrivateTmp=yes`、`NoNewPrivileges=yes`、`CapabilityBoundingSet=`（清空）、`RestrictAddressFamilies=AF_INET AF_INET6`、`MemoryMax=`。
- **关键点**：**Hermes 不直接持有 ops 私钥**，而是把命令交给这个隔离单元执行 ⇒ 注入内容触达不到密钥，也触达不到宿主关键路径。Hermes 侧仍是 `terminal('guga-remote <别名> -- <cmd>')`（薄包装，进沙箱）。

**C. 身份隔离**
- 专用无特权用户 `gugaops` 跑执行体（持有 ops 私钥）；与 Hermes（`ubuntu`）、Caddy（容器）、code-server 的运行身份**分离**。隧道用户 `tunnel` 再单独一个。

**D. 最小权限 & 审计**
- ops 私钥 `600`、**只读**挂载进沙箱；审计日志写在沙箱**外面**（宿主机 `~/stack/remote/audit.log`）；guest 临时 key 用完即删。

> **取舍**：容器化会把 "Hermes 直接 `ssh 别名`" 变成 "Hermes 调沙箱执行体"，多一层胶水，换来明确边界；systemd 硬化版更轻但边界略弱。二选一见「我替你拍板的点」。

#### 10.2 后端：**新增独立服务** `guga-join-api`（:8793，账户 `gugajoin`）
**为什么不并进 `remote-api.py`**：那是**唯一要挂公网**的东西。`remote-api.py` 手里有 `~/.ssh/guga_ops`（能登**所有自有机器**）、`hosts.json`、记忆——一处 RCE 就全丢。拆开后 `gugajoin` **读不到 `~/stack`**（`/home/ubuntu` 是 750）、没有 ops 密钥，爆炸半径只剩"已同意被协助的 guest"。

#### 10.3 **关键发现**：临时密钥怎么进 sshd —— 用 `AuthorizedKeysCommand`（**不用 sudo、不改硬化**）
现状：`AuthorizedKeysFile /etc/guga/tunnel_authorized_keys` 是 `640 root:tunnel`，服务写不了；而 `StrictModes yes` 又要求 key 文件属主是 root/目标用户、不可 group/other 写 → "服务可写的普通文件"**天然不合法**。

**做法**（已核对 `man 5 sshd_config`：`AuthorizedKeysCommand`/`AuthorizedKeysCommandUser` **可出现在 `Match` 块内**，且**在 `AuthorizedKeysFile` 之后尝试**）：
- 在现有 `Match User tunnel` 里追加：
  ```
  AuthorizedKeysCommand /usr/local/bin/guga-join-keys %u
  AuthorizedKeysCommandUser gugajoin
  ```
- helper `/usr/local/bin/guga-join-keys`（**root:root 0755**，sshd 强制要求）只做一件事：`cat /run/guga-join/authorized_keys`（tmpfs，由 join 服务以 `gugajoin` 身份写）。
- **自有机器不受影响**：`win-asus` 那行在静态文件里先命中，就不会跑命令（**第 6 步必须实测 `ssh win-asus hostname` 仍通**）。
- 被攻陷极限**不变**＝占一个回环端口（`PermitListen` 限死、`PermitOpen none`、无 pty/agent/X11、`ForceCommand nologin`）。
- `PermitListen` 从 `22022-22025` **扩到 `22022-22039`**（多 15 个 guest 槽；22022 仍归咕嘎五号）。

#### 10.4 systemd（比 remote-api 更严 —— 公网面）

#### 10.5 "无痕"怎么落地 + 怎么自证
| 项 | 落点 | 撤销 | 检查 |
|---|---|---|---|
| token / guest 注册表 | **进程内存** | TTL / 撤销 / 重启 | `systemctl restart guga-join-api` |
| guest 隧道公钥 | **`/run/guga-join/authorized_keys`（tmpfs）** | 删 key / 重启 | `ls -A /run/guga-join` → 空 |
| guest 临时服务器密钥 | **`/run/guga-join/<id>/id_guest`（tmpfs）** | 同上 | 同上 |

| 服务器审计 | **不写** `~/stack/remote/audit.log` | — | `grep -c <对方用户名> ~/stack/remote/audit.log` → 0 |

**操作记录写回对方机器本地**：装到 guest 的 authorized_keys 那行带 `command="…"`（forced command）。sshd 把服务器发来的命令放进 `SSH_ORIGINAL_COMMAND`，包装器**先记账再执行**：
- Windows `C:\guga\guga-exec.ps1` → `%USERPROFILE%\.guga\audit.log`
- Linux `~/.guga/exec`（`chmod +x`）→ `~/.guga/audit.log`

## 安全（前置与边界）

- **认证（密码 + TOTP）为对外硬前置**：现状 Caddy `:8080` 零认证。在认证完成前，第③页管理面与任何 enroll 端点**只能回环/隧道可达**（不给公网开新端口）。对应设计文档「组件 7 认证与安全」。
- **沙箱（§8）为硬要求**：入站受限入口 + 执行隔离单元 + 身份隔离 + 最小权限/审计，保证目标机被攻陷或返回注入内容时，服务器核心（Hermes/Caddy/Gitea/code-server/`~/.ssh`/凭证）不受影响。
- **最小权限**：guest key 一律 `expiry-time` + 只在需要时 `pty`，用完即删；隧道 key 用 `restrict,permitlisten=...` 锁死到单一回环端口。
- **审计**：`~/stack/remote/audit.log`（ts/host/cmd/kind/approver/exit）；Hermes 侧工具调用本就落 `~/.hermes/state.db`。
- **禁止**：cron 不得触发 guest 动作（无人值守）。

## 我替你拍板的点（如不同意，实施前告诉我改）

1. **主机动向**：`hosts.json` 为真相 + 生成 ssh 片段（而非"ssh config 即真相"）。
2. **保活留物**：接受"计划任务/unit + ps1"（换取长期稳定），而非真零残留。
3. **操作层粒度**：own 只读自动放行 + 写/危险确认；guest 一律确认。
4. **他人机器接入**：**浏览器同意页**（标题「咕嘎一号请求访问」）+ 一次性命令 + 临时反向通道；**整条线后置到备案 + HTTPS 就绪之后**（P5）。
5. **远端网页终端**：放到 P5（认证之后）——它是第③页最大攻击面。
6. **隧道密钥/端口**：每台目标机独立隧道 key，**改用专用 `tunnel` 用户 + 独立隧道端口（2222）** + `restrict,permitlisten` 限制项；回环端口从 22022 起。
7. **沙箱实现选型**：执行隔离用 **Docker 容器（方案 1，推荐）** 还是 **systemd 硬化（方案 2，更省 4G 内存）**？我倾向先用 **systemd 硬化**（本机仅 4G，且少一层容器网络/密钥传递的复杂度），边界不够再升级到容器。
8. **guest 无痕 & 记录归属**：服务器对 guest **不落盘任何东西**；对其操作记录写回**对方机器本地**（`~/.guga/audit.log` / `%USERPROFILE%\.guga\audit.log`）。
